## Decision (the rule)

Localization is generated by odyssey-cli / `odyssey-contribution-tooling` from source
`.properties` files into checked-in, typed `i18n.generated/*.ts` outputs (with a pseudo-locale
for testing). Contributions translate into the `enduser` namespace. Generated files are not
hand-edited.

## What was rejected

1. A hand-rolled `properties-to-ts.ts` conversion script (removed once the tooling existed).
2. Hand-writing or hand-editing the generated TypeScript i18n files directly — they are build
   artifacts and get overwritten.

## Why

Typed, generated i18n gives compile-time verification that a translation key exists (via
`TypedTFunction`) and keeps every locale in sync with the `.properties` source. Hand-maintained
translation objects drift and produce runtime "missing key" failures. The `enduser` namespace
is an Okta convention (the "enduser dashboard") — do not rename it based on cspell warnings.

## How to honor it

- Edit the source `.properties` files, then regenerate — never edit `i18n.generated/*`.
- New translated strings for contributions go in the `enduser` namespace.
- Preserve the `enduser` spelling (one word); it is domain terminology, not a typo.
- Button-label assertions in tests use `odysseyTranslate` from `i18n.generated/i18n.js`.
